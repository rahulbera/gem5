# VTAGE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement VTAGE per
`docs/superpowers/specs/2026-08-03-vtage-design.md` on the existing VP
framework, through Stage-III/IV evaluation.

**Architecture:** Params-free `VtageTables` core (7 banks, on-demand
TAGE-style folds from per-instruction history snapshots, FPC confidence
with injectable RNG) under a `VtageVP` SimObject; framework generalized
with `VpLookupContext`/result-token plumbing, a per-predictor
`trainAtCommit` knob whose verify-site corrective reset carries the
no-livelock invariant, and a VP-private speculative history subsystem
(fetch-side updates + per-initiator restores).

**Tech Stack:** as the LVP campaign (SCons, SimObject codegen, GTest,
`configs/garfield/arm` drivers, gem5-infra microbenchmarks).

### Task 1: Params-Free VTAGE Core (`VtageTables`) + GTests

**Files:** Create `src/cpu/o3/vp/vtage_tables.{hh,cc}`,

**Interfaces produced (later tasks rely on these exact shapes):**

```cpp
// vp_history.hh (params-free)
struct VpHistSnapshot { uint64_t ghr = 0; uint16_t path = 0; };
struct VpHistory
{
    VpHistSnapshot state;
    void branchShift(bool taken) { state.ghr = (state.ghr << 1) | taken; }
    void takenTarget(Addr target, unsigned pathBits)
    { state.path = ((state.path << 3) | ((target >> 2) & 7)) &
                   ((1u << pathBits) - 1); }
    void restore(const VpHistSnapshot &s) { state = s; }
};

// vtage_tables.hh (params-free)
struct VtageConfig
{
    unsigned baseEntries = 8192;
    unsigned taggedEntries = 1024;
    unsigned numTagged = 6;               // <= 7 (3b biased rank)
    std::vector<unsigned> historyLengths = {2, 4, 8, 16, 32, 64};
    unsigned baseTagBits = 12;            // tag = baseTagBits + rank
    unsigned confBits = 3;
    unsigned confThreshold = 7;           // fatal_if < 1
    std::vector<double> fpcVector =
        {1, 1./16, 1./16, 1./16, 1./16, 1./32, 1./32};
    unsigned pathBits = 16;
};
struct VtageLookup
{
    bool hit = false;        // some component matched (incl. VT0 always)
    bool confident = false;  // provider c >= confThreshold
    RegVal value = 0;
    uint64_t token = 0;      // biased-rank packed; never 0 for a lookup
};
enum class VtageTrainOutcome
{ CorrectInc, CorrectSat, WrongReset, WrongValOverwrite,
  Allocated, AllocFailedAged, StaleTokenRecomputed };
class VtageTables
{
  public:
    // rng: any callable double() in [0,1) — injectable for GTests.
    VtageTables(const VtageConfig &cfg, std::function<double()> rng);
    VtageLookup lookup(Addr pc, MicroPC upc,
                       const VpHistSnapshot &h) const;
    // Full commit-side train. token==0 => recompute provider from
    // (pc, upc, h). Returns the outcomes that fired (bitmask or
    // small vector — implementer's choice, GTest-visible).
    std::vector<VtageTrainOutcome> train(Addr pc, MicroPC upc,
        const VpHistSnapshot &h, uint64_t token, RegVal actual);
    // Verify-site corrective reset: c=0/u=0 through the token,
    // tag-checked; returns false on stale token (counted by caller).
    bool correctiveReset(uint64_t token);
};
```

- [ ] **Step 1: Read the anchors.** `.superpowers/sdd/tage-folds.md` —
  transcribe the `FoldedHistory` update arithmetic, `gindex`, `gtag`,
  and `F()` path hash EXACTLY (adapted to on-demand folding: fold the
  64-bit snapshot slice `h.ghr[0:L(i)]` by iterating the update step L
  times from zero state, or equivalently implement the closed-form
  fold; GTest pins equivalence on known vectors). PC pre-shift: use
  `pc XOR (upc << 48)` as the "pc" input (µPC separation), then
  `>> 2` in place of the brief's `instShiftAmt`.
- [ ] **Step 2: Tests first** (`vtage_tables.test.cc`, injectable RNG
  = a scripted sequence). Pin at minimum: fold determinism (same
  snapshot ⇒ same indices/tags; differing bit L-1 changes component i
  with L(i) > that bit only); longest-match provider selection; VT0
  fallback; threshold gating (c==6 no predict, c==7 predict, and with
  confThreshold=1, c==1 predicts); FPC: with rng scripted to 0.0
  every increment fires, scripted to 0.99 only v[i]=1 transitions
  fire; wrong ⇒ unconditional reset regardless of rng; val-overwrite
  only when c was already 0; u = correct; allocation: rank>provider
  only, u==0 candidates, scripted-rng choice, aging on none;
  corrective reset via token incl. stale-tag ⇒ false and VT0-token
  (biased rank 1, index 0) distinct from token 0; train with token 0
  recomputes provider.
- [ ] **Step 3: Implement** `vtage_tables.{hh,cc}` per the spec's
  algorithm sections (biased-rank token pack/unpack with
  construction-time `fatal_if` geometry asserts; `fatal_if
  (confThreshold < 1)`; keep the core free of SimObject/stat/params
  includes).
- [ ] **Step 4: Register + build + run.** SConscript:
  `Source('vtage_tables.cc')`,
  `GTest('vtage_tables.test', 'vtage_tables.test.cc',
  'vtage_tables.cc')`. Build the GTest target only; all tests pass.
- [ ] **Step 5: Controller commit.** Suggested header:

### Task 3: Pipeline Wiring (History Updates/Restores, Commit Train, Corrective Reset)

**Files:** Modify `fetch.cc`, `bac.cc`, `commit.{hh,cc}`,
`lsq_unit.cc`, `iew.cc`, `cpu.{hh,cc}` if a pointer path is needed.

Anchors and exact insertion points are in
`.superpowers/sdd/fetch-history.md` and
`.superpowers/sdd/commit-train.md`; the binding rules:

1. **Stamp + update at the BAC choke point** (`BAC::updatePC`, called
   per instruction right after `buildInst`): stamp
   `inst->setVpHistSnap(pre-update state)` for EVERY instruction; for
   conditional branches `branchShift(predict_taken)`; for every taken
   control transfer `takenTarget(target)`. Guard the whole block on an
   attached predictor with `usesHistory()` (LVP/baseline untouched).
2. **Restores per the spec's per-initiator table.** All back-end
   redirects funnel through `Fetch::checkSignalsAndUpdate`
   (fromCommit before fromDecode); use the squash-inst provenance
   documented in the brief (commit: `squashInst` +
   `commitInfo.branchTaken` + `mispredictInst`; squashAfter:
   advance-past-self; traps: exact restore; decode:
   `squashFromDecode` with decode-resolved outcome; `bacResteer`
   needs no restore). Each restore path increments a per-initiator
   stat.
3. **Commit train hook** at `Commit::commitHead` after
   `updateComInstStats(head_inst)` (brief: past all early-outs,
   physreg provably live): in-scope + `trainsAtCommit()` ⇒ read dest
   physreg, `vp->train(inst, actual)`. Commit caches the `valuePred`
   pointer MRN-style (ctor from `params.valuePred`).
4. **Writeback sites** (`lsq_unit.cc` load verify, `iew.cc` non-load
   verify): when `trainsAtCommit()`, skip the `train()` call, and in
   the verify-WRONG arm call `vp->correctiveReset(inst->vpToken())`
   BEFORE the squash trigger (LVP's proven ordering); count stale
   returns. Verify/squash/doomed-window logic otherwise untouched.
- [ ] Steps: implement (anchors from briefs), full build, GTests, LVP
  bit-identity gate again (nothing in this task may fire with LVP
  attached — every new call is behind `usesHistory()` /
  `trainsAtCommit()`), baseline inertness (no `--use-vp`: zero new
  work), controller commit. Suggested header:
  `cpu-o3: Wire VP history and commit-time training`

### Task 5: Stage-III (`vphist`) + Stage-IV (Both Scopes)

- **`vphist`** (gem5-infra `src/vphist/`, conventions of
  vpchase/vpalu): a single-PC integer load whose value is a function
  of a branch-direction pattern with phase-unique windows (e.g. a
  period-7 direction sequence selecting between two table slots
  written before the ROI). Constraints from the spec review: the
  branch must SURVIVE compilation (aarch64 if-converts this shape to
  csel — use an asm-opaque taken arm or `-fno-if-conversion`, and
  verify a `b.cond` exists in the loop by disassembly); value stream
  delivered through one same-PC load so loads-only scope covers it.
  Expected: LVP coverage ~0 on that PC; VTAGE coverage → high with
  accuracy ~1.
- Stage-III runs: vpchase/vpalu/vphist × {base, lvp, vtage(+all where
  relevant)}.
- **Stage-IV:** extend the existing sweep driver's CONFIGS with
  `vtage` (`--use-vp vtage`) and `vtage_all` (`+ --vp-all-insts`);
  reuse `base`; aggregate 5-way (base, lvp, lvp_all, vtage,
  vtage_all) with the established tooling; carry the
  coverage-denominator caveat into the analysis.
- [ ] Steps: bench + build + disasm proof (gem5-infra commit), runs,
