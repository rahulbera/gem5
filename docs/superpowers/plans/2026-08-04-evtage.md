# E-VTAGE Implementation Plan (EVES Stage 1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement E-VTAGE per
`docs/superpowers/specs/2026-08-04-evtage-design.md` and run the
iso-geometry policy A/B against plain VTAGE.

**Architecture:** A params-free `EVtageTables` core (forked from
`VtageTables` — the policies diverge too much for clean subclassing;
shared fold helpers stay in common headers) under an `EVtageVP`
SimObject; no pipeline-stage changes (the framework contract from the
VTAGE campaign carries everything — token, corrective punish, commit
train, history). One framework extension: the classifier context
(`VpClassifierInfo`) passed to `trainImpl`/punish per the spec's
Framework API Changes section.

**Tech Stack:** as the VTAGE campaign.

## Global Constraints

Identical to the VTAGE plan's (commit ceremony via controller, build
discipline, LVP/VTAGE bit-identity preservation) plus:

- **The spec is normative and its formulas are verbatim-transcribed
  law** — implementers transcribe from the spec, not from memory of
  TAGE idioms; the spec's GTest-pinned lifecycle endpoints are
  acceptance criteria.
- The code brief `.superpowers/sdd/eves-code-brief.md` and the CVP
  source in the scratchpad resolve any residual ambiguity; disputes
  between spec and brief are escalated, not resolved silently.
- **VTAGE bit-identity gate:** plain `vtage` runs must remain
  byte-identical after every task (E-VTAGE is additive; shared-header
  edits must not perturb `VtageTables`).

## Tasks

### Task 1: Params-Free E-VTAGE Core + GTests

Create `src/cpu/o3/vp/evtage_tables.{hh,cc}`, `evtage_tables.test.cc`;
SConscript Source+GTest lines. Fork `VtageTables`' structure; implement
per spec: the classifier-driven confidence gate (E exponent + VT0
doubling), both punish arms with u side-effects and the
`punishApplied`/`medConfPending` bits, unconditional value overwrite on
wrong trains, the K32 allocation gate (outer operand gate for
alu/store/undef, `E'` body, MedConf deterministic body) with BOTH
landing arms and seeds, UPDATEU + deterministic u++ at saturation,
2-bit u, TICK (`NA − 5·ALL`, ≥1024 pass), tagged 2-way skewed base
with no-provider (rank-0) lookups, burst-guard counter hooks
(window param), injectable RNG throughout. Tests-first per the spec's
Testing Gates 1 list — every formula term, both arms of every rule,
the pinned delivered-wrong endpoint `{c=5, u=1, value corrected}`,
pending-bit lifecycle including stale-tag and reallocation-clears
cases. Gate: GTest target green; vtage_tables suite untouched.
Suggested header: `cpu-o3: Add params-free E-VTAGE core tables`

### Task 2: Classifier Context + `EVtageVP` SimObject + CLI

Framework: add `VpClassifierInfo {isLoad, memLevel, opClassBucket,
intSrcCount, isIndirectCall, value}` built by the base class at
train/verify sites per the spec's mappings (MemSrcLevel; OpClass
buckets; integer-non-flag source count; `isIndirectCtrl() &&
isCall()`), threaded to `trainImpl` and the corrective-punish path;
rename-count hook for the burst guard (per-thread renamed-instruction
counter the predictor may read). LVP/VTAGE implementations ignore it —
**bit-identity gate for both** (smoke `b_vp_lvp` + one vtage sweep
checkpoint rerun, stats value-identical). `EVtageVP` SimObject
(`--use-vp evtage`, `--evtage-burst-guard`), stats per the spec's
Statistics section. Full build; smoke matrix additions: evtage on
vpchase/vphist + the hostile threshold-1 run with the spec's bounded
re-delivery pass criterion + checksum gates.
Suggested header: `cpu-o3,configs: Add the E-VTAGE value predictor`

### Task 3: Probe A/B + 190 Both Scopes

Probe (16 checkpoints, runs/vp_evtage_probe/): `evtage` vs the
committed `vtage` results at identical geometry; decision gate: if the
probe is not clearly negative, promote to the 190 sweep configs
`evtage` + `evtage_all` (extend the main sweep driver; reuse
baselines). Analysis: the 7-way (now) comparison incl. wrong-volume,
provider distributions, burst-guard-off confirmation, and the
tagged-base confound note. Feed the eventual EVES report.
